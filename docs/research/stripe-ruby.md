# stripe-ruby: design research for teachmehipaa-ruby

Source: shallow clone of `stripe/stripe-ruby` at `94490f760b89` (2026-11-12, gem
v21.0.0, pinned API `2026-10-28.endive`) in `~/scratch/stripe-src/stripe-ruby`,
plus docs.stripe.com. All GitHub links are pinned to that commit:
`B = https://github.com/stripe/stripe-ruby/blob/94490f760b89`.

## TL;DR

1. Gem name `stripe`, Ruby `>= 3.0`, **two runtime deps only** (`bigdecimal`, `logger`); HTTP is stdlib `net/http`, so it is effectively zero-dep.
2. Ships Sorbet **RBI** (`rbi/stripe.rbi`, generated), **no RBS**. No Zeitwerk: it uses manual `require` for the core plus stdlib `autoload` for about 1,760 generated constants, and `Stripe.eager_load!` / a Railtie for pre-fork.
3. Recommended style is `Stripe::StripeClient.new(key).v1.customers.create(...)`. The global `Stripe.api_key` + `Stripe::Customer.create` style is "legacy" and new endpoints land only in StripeClient.
4. Almost everything is generated from OpenAPI (resources, services, params, RBI, v2 error classes). Hand-written code is the core: requestor, connection manager, config, list objects, webhook, errors base.
5. Per-request options go in a second positional hash: `(params = {}, opts = {})`. Known keys are `api_key`, `idempotency_key`, `stripe_account`, `stripe_context`, `stripe_version`. Any other key becomes an HTTP header.
6. Retries default to 2 (exponential backoff 0.5s to 5s cap, with jitter). They honor `Stripe-Should-Retry`, retry 409, 429 `lock_timeout` and 5xx, and **ignore `Retry-After`**. POST/DELETE get an auto `Idempotency-Key` (UUIDv4) whenever retries > 0.
7. Errors: `StripeError < StandardError` carries `http_status`, `http_body`, `json_body`, `http_headers`, `code`, `request_id` and `error`. v1 maps errors by HTTP status, v2 by the `error.type` string.
8. Transport is one `ConnectionManager` per thread per config. It keeps a persistent `Net::HTTP` per host:port with a 30s keep-alive, and disables Net::HTTP's own retries.
9. Webhooks: HMAC-SHA256 over `"#{t}.#{payload}"`, header `t=..,v1=..`, 300s tolerance, constant-time compare. Newer "thin events" use `client.parse_event_notification` plus a typed notification handler.
10. Tests use test-unit + shoulda-context + mocha + webmock against **stripe-mock** (an OpenAPI-driven mock server). CI covers MRI 3.0–3.4, JRuby and TruffleRuby. Publishing uses RubyGems trusted publishing (OIDC). The changelog is generated by the `hark` tool.

## 1. Repo layout, gemspec, runtime, typing, loading

**Layout** (top level of clone):

```
lib/stripe.rb                 # entrypoint: stdlib requires, core requires, globals
lib/stripe/*.rb               # hand-written core (requestor, client, config, errors...)
lib/stripe/api_operations/    # Create/List/Delete/Save/Search/NestedResource/Request mixins
lib/stripe/resources/  (+v2/) # generated resource classes (legacy style + response types)
lib/stripe/services/   (+v2/) # generated service classes (StripeClient style)
lib/stripe/params/            # generated typed request-param classes
lib/stripe/events/            # generated thin-event notification classes
lib/data/ca-certificates.crt  # bundled CA bundle
rbi/stripe.rbi + rbi/stripe/  # Sorbet RBI (generated + a few hand-written)
sorbet/ test/ examples/ exe/stripe-console .hark/ (changelog fragments)
CODEGEN_VERSION OPENAPI_VERSION VERSION justfile Makefile(deprecated) Rakefile
```

**Gemspec** ([`stripe.gemspec`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/stripe.gemspec)):

```ruby
s.required_ruby_version = ">= 3.0.0"
s.add_dependency "bigdecimal"   # needed on 3.4+ for decimal_string coercion
s.add_dependency "logger"
s.metadata = { ..., "rubygems_mfa_required" => "false" }
s.files = `git ls-files`.split("\n").grep(included)  # lib/, exe/, rbi/stripe.rbi + 3 hand RBIs
```

- The **HTTP stack is stdlib** (`net/http`, `openssl`, `json`, `securerandom`, `uri`, `cgi/escape`), required in [`lib/stripe.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe.rb) lines 1–17. There is no Faraday or httpx.
- `rubygems_mfa_required` is `"false"` because publishing is OIDC trusted publishing from CI (§12).
- The **min Ruby version** is 3.0, and 3.0–3.2 are marked "deprecated". Per the docs, Ruby EOL is followed by "an extended support window of *1.5 years* (three major API releases)" ([docs.stripe.com/sdks/versioning](https://docs.stripe.com/sdks/versioning?lang=ruby)).
- **Typing**: Sorbet RBI only. The README says "we only support RBIs at the moment", and the combined RBI is packed at `rbi/stripe.rbi` "to decrease Tapioca loading time" ([README.md](https://github.com/stripe/stripe-ruby/blob/94490f760b89/README.md), "Types"). Type changes ship in **minor** releases and are not covered by semver. Runtime files carry `# typed: true` sigils in places ([`lib/stripe/stripe_service.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_service.rb)). `sorbet/config` ignores `rbi/stripe.rbi` for self-checking. CI runs `srb tc` (`just typecheck`).
- **Loading**: there is no Zeitwerk. The core uses explicit `require` ([`lib/stripe.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe.rb) lines 18–60). Generated constants use stdlib `autoload`: `lib/stripe/resources.rb` has 839 entries, `services.rb` 220 and `params.rb` 701, for example `autoload :Customer, "stripe/resources/customer"`. `Stripe.eager_load!` ([`lib/stripe.rb#L159`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe.rb#L159)) is "recommended before forking". [`lib/stripe/railtie.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/railtie.rb) adds `Stripe` to `config.eager_load_namespaces`.

## 2. Usage styles

**StripeClient (recommended)**, from [README.md](https://github.com/stripe/stripe-ruby/blob/94490f760b89/README.md) "Usage":

```ruby
client = Stripe::StripeClient.new("sk_test_...")
customers = client.v1.customers.list()
customer  = client.v1.customers.retrieve("cus_123")
client.v2.core.events.list
```

- `StripeClient#initialize(api_key, stripe_account:, stripe_context:, stripe_version:, api_base:, uploads_base:, connect_base:, meter_events_base:, client_id:)` ([`stripe_client.rb#L19`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_client.rb#L19)). It raises `AuthenticationError` if `api_key` is nil.
- It builds a private `APIRequestor` and the top-level `V1Services` / `V2Services` trees. Each service receives the requestor and instantiates its sub-services eagerly (`CustomerService#initialize` news up `@tax_ids` and others), as seen in [`services/customer_service.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/services/customer_service.rb).

**Legacy global style**:

```ruby
Stripe.api_key = "sk_test_..."
Stripe::Customer.create(email: "a@b.c")
cus = Stripe::Customer.retrieve("cus_123"); cus.delete
```

- [README "StripeClient vs legacy pattern"](https://github.com/stripe/stripe-ruby/blob/94490f760b89/README.md): legacy "will be marked as deprecated soon … new API endpoints will only be accessible in the StripeClient." v2 resources raise `NotImplementedError` on `resource_url` / `retrieve`, which tells the user to use StripeClient ([`api_resource.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_resource.rb), `self.resource_url`, `self.retrieve`).
- The global config is a module-level `StripeConfiguration` exposed through `def_delegators` ([`lib/stripe.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe.rb) lines 92–145).

**Gotcha (important for us)**: `StripeClient::CLIENT_OPTIONS` covers only keys and base URLs ([`stripe_client.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_client.rb)). **Timeouts, retries, proxy, logger, CA bundle and telemetry cannot be set per client.** `StripeConfiguration.client_init` copies them from the **global** `Stripe.config` ([`stripe_configuration.rb#L43`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_configuration.rb#L43)), so StripeClient is "instance auth plus global transport". We should not copy this.

## 3. Configuration (`Stripe::StripeConfiguration`)

[`lib/stripe/stripe_configuration.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_configuration.rb), defaults in `#initialize` (L67):

| Option | Default | Notes |
|---|---|---|
| `max_network_retries` | `2` | coerced `to_i` |
| `initial_network_retry_delay` / `max_network_retry_delay` | `0.5` / `5` (s) | internal; setters `to_i`, so a setter would truncate 0.5 to 0 |
| `open_timeout` / `read_timeout` / `write_timeout` | `30` / `80` / `30` | each setter calls `APIRequestor.clear_all_connection_managers(config: self)` |
| `api_base`, `uploads_base`, `connect_base`, `meter_events_base` | `https://api.stripe.com` etc. | also rebuilds `base_addresses` (`:api`, `:files`, `:connect`, `:meter_events`) |
| `proxy` | nil | parsed into `Net::HTTP.new(host, port, p_host, p_port, p_user, p_pass)` |
| `verify_ssl_certs` | true | false triggers a one-time `warn` |
| `ca_bundle_path` | bundled `lib/data/ca-certificates.crt` | `ca_store` is memoized as an `OpenSSL::X509::Store` |
| `log_level` | nil (or `ENV["STRIPE_LOG"]`) | `LEVEL_DEBUG/INFO/ERROR` map to stdlib `Logger` levels |
| `logger` | nil | any `Logger`-compatible object; when set, `log_level` is ignored |
| `enable_telemetry` | true | sends `X-Stripe-Client-Telemetry` (§9) |
| `api_version` | `ApiVersion::CURRENT` | pinned per gem release ([`api_version.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_version.rb)) |

- **Thread-safety notes.** Config is a plain mutable object. `ca_store` is "itself not thread safe", and the docs tell users to call `Stripe.ca_store` at init time ([`stripe_configuration.rb#L196`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_configuration.rb#L196)). `#key` joins all instance variables except account/context, giving the connection-manager cache key (L210). `#inspect` is overridden so it never prints the API key or proxy credentials (L91). The same applies to `StripeClient#inspect` and `APIRequestor#inspect`.
- **Pooling.** There is no pool. Each thread gets its own `ConnectionManager` per config key ([`api_requestor.rb#L106`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_requestor.rb#L106), stored in `Thread.current[:api_requestor__internal_use_only]`, L434). Each manager holds one persistent `Net::HTTP` per `[host, port]`, guarded by a mutex ([`connection_manager.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/connection_manager.rb)). Idle managers are garbage-collected after 120s, checked every 60s (`CONNECTION_MANAGER_GC_*`, [`api_requestor.rb#L330`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_requestor.rb#L330)).

## 4. Resource / service organization

**Generated vs hand-written**: files begin `# File generated from our OpenAPI spec`. Hand-edited generated files use marker comments such as `# attr_readers: The beginning of the section generated from our OpenAPI spec` ([`stripe_client.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_client.rb), [`api_requestor.rb#L884`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_requestor.rb#L884)). `CODEGEN_VERSION` and `OPENAPI_VERSION` record the inputs. The generator (`sdk-codegen`) is private; the `justfile` does `import? '../sdk-codegen/utils.just'`.

**Services (new style)** are thin, explicit and generated. Each method has the signature `(path_ids..., params = {}, opts = {})` ([`services/customer_service.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/services/customer_service.rb)):

```ruby
class CustomerService < StripeService
  def retrieve(customer, params = {}, opts = {})
    request(method: :get,
            path: format("/v1/customers/%<customer>s", { customer: CGI.escape(customer) }),
            params: params, opts: opts, base_address: :api)
  end
end
```

`StripeService#request` delegates to `@requestor.execute_request(..., usage: ["stripe_client"])` ([`stripe_service.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_service.rb)). Path IDs are always `CGI.escape`d.

**Resources (legacy style)** compose `APIOperations` mixins ([`resources/customer.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/resources/customer.rb) L7–23):

```ruby
class Customer < APIResource
  extend  Stripe::APIOperations::Create   # self.create(params, opts)
  include Stripe::APIOperations::Delete   # self.delete(id) + #delete
  extend  Stripe::APIOperations::List     # self.list(filters, opts)
  extend  Stripe::APIOperations::Search
  include Stripe::APIOperations::Save     # self.update(id, ...) + deprecated #save
  extend  Stripe::APIOperations::NestedResource
  nested_resource_class_methods :tax_id, operations: %i[create retrieve delete list]
```

The mixins live in [`lib/stripe/api_operations/`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_operations/). `NestedResource` metaprograms `create_tax_id` / `list_tax_ids` and similar ([`nested_resource.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_operations/nested_resource.rb)).

**Custom methods**: `APIResource.custom_method(name, http_verb:, http_path:)` delegates to `Util.custom_method`. It only allows `:get/:post/:delete` and defines `self.<name>(id, params, opts)` posting to `"#{resource_url}/#{id}/#{http_path}"` ([`util.rb#L63`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/util.rb#L63)). The current generated code does not call it; it emits explicit methods instead (e.g. `Customer#create_funding_instructions` plus a class-method twin, [`customer.rb#L252`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/resources/customer.rb#L252)). So `custom_method` is legacy plumbing.

**`StripeObject` dynamic accessors** ([`stripe_object.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_object.rb)): it wraps a `@values` hash and `define_method`s readers, writers and `?` predicates per key on the singleton class (`add_accessors`, L438). It has `method_missing`/`respond_to_missing?` (L490) and `[]` indexer access. In the README, `customer.unknown` raises `NoMethodError` while `customer['unknown']` returns nil. `last_response` exposes `http_status` / `http_headers`. Newer generated classes also declare `attr_reader` per field and nested inner classes (`Customer::Address`) for docs and RBI. `Util.convert_to_stripe_object` picks the class from the JSON `object` field.

**Typed params**: generated `Stripe::CustomerCreateParams < RequestParams` with kwargs constructors and nested classes. `RequestParams.new` records `@_explicitly_set_keys`, so explicit `nil` survives for v2 JSON ([`request_params.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/request_params.rb), [`params/customer_create_params.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/params/customer_create_params.rb)). Plain hashes are still accepted everywhere.

**v1/v2 namespaces**: `client.v1.*` (form-encoded bodies, `object`-typed) and `client.v2.<area>.*` (JSON bodies) live under `Stripe::V2::*` modules ([`services/v2/core/event_service.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/services/v2/core/event_service.rb)). The API mode is inferred from the path prefix (`Util.get_api_mode(path)`). v2 bodies are `JSON.generate`d with `Content-Type: application/json`; v1 bodies are `application/x-www-form-urlencoded` ([`api_requestor.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_requestor.rb), `encode_body`, ~L592).

## 5. Per-request options

```ruby
client.v1.customers.list({}, { api_key: "sk_...", stripe_account: "acct_...",
                               stripe_version: "2018-02-28", idempotency_key: "k1",
                               "X-Custom" => "v" })
```

[`request_options.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/request_options.rb):

- `OPTS_USER_SPECIFIED = [:api_key, :idempotency_key, :stripe_account, :stripe_context, :stripe_version]`.
- `extract_opts_from_hash` moves known keys out, and **"remaining user-provided opts should be treated as headers"**.
- Non-string values raise `ArgumentError`.
- `merge_config_and_opts` gives request options precedence over config.
- `OPTS_PERSISTABLE` excludes `idempotency_key`. Returned objects remember account/context/key for follow-up calls (`RequestOptions.persistable`), but never the idempotency key.
- Putting option keys in `params` triggers a `warn` (`warn_on_opts_in_params`, [`api_operations/request.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_operations/request.rb)).
- `StripeClient#with_stripe_context(ctx)` returns a cloned client scoped to a new tenant context ([`stripe_client.rb#L125`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_client.rb#L125)).

## 6. Pagination

- **v1 `ListObject`** ([`list_object.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/list_object.rb)): `include Enumerable`; `#each` iterates only the current page. `#auto_paging_each` returns `enum_for(:auto_paging_each)` without a block (so `.lazy`, `.first(n)` and `.each_slice` work). It loops with `next_page`, which uses `starting_after: data.last.id` and stops when `has_more` is false. If the original filters had `ending_before`, it walks backwards with `previous_page` and `reverse_each`. It rescues `LocalJumpError` for `break` (L70).
- **v1 `SearchResultObject`** uses an opaque `next_page` token: `filters.merge(page: next_page)` ([`search_result_object.rb#L64`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/search_result_object.rb#L64)).
- **v2 `V2::ListObject`** follows a server-provided **`next_page_url`** (an opaque cursor URL) with `fetch_next_page` ([`v2_list_object.rb#L51`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/v2_list_object.rb#L51)). The client keeps no filter state, which makes v2 the closest analogue to our cursor pagination. v2 search does the same ([`v2_search_result_object.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/v2_search_result_object.rb)).

```ruby
client.v1.customers.list(limit: 100).auto_paging_each { |c| ... }
client.v1.customers.list.auto_paging_each.lazy.select { ... }.first(10)
```

## 7. Errors

[`lib/stripe/errors.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/errors.rb):

```
StandardError
└─ StripeError  (message, code, error, http_body, http_headers, http_status, json_body, request_id, response)
   ├─ AuthenticationError (401)   ├─ PermissionError (403)   ├─ RateLimitError (429)
   ├─ InvalidRequestError (400/404, +param)   ├─ IdempotencyError (type=idempotency_error)
   ├─ CardError (402, +param)     ├─ APIError (other / unparseable)
   ├─ APIConnectionError (network/TLS; wraps original message)
   ├─ SignatureVerificationError (+sig_header)
   ├─ OAuth::OAuthError → InvalidClientError, InvalidGrantError, InvalidRequestError,
   │                       InvalidScopeError, UnsupportedGrantTypeError, UnsupportedResponseTypeError
   └─ (generated v2) AlreadyCanceledError, NotCancelableError, QuotaExceededError,
      CannotProceedError(+reason), InvalidPaymentMethodError(+invalid_param), ... (~20)
```

- **Attributes**: `request_id` comes from the `request-id` header. There is a private `@idempotent_replayed` flag from `idempotent-replayed`. `error` is a typed `ErrorObject` built from `json_body[:error]`. `to_s` renders as `"(Status 402) (Request req_x) msg"`.
- **Mapping** ([`api_requestor.rb#L768`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_requestor.rb#L768)):
  - `handle_error_response` parses the body. If `error` is missing or the JSON is invalid, it raises `APIError` ("Invalid response object from API").
  - If `error` is a String, it is an OAuth error (keyed by RFC 6749 code).
  - For v2, `specific_v2_api_error` maps on `error_data[:type]` and falls back to v1.
  - For v1, `specific_api_error` maps on HTTP status (L812).
- **Network errors**: `NETWORK_ERROR_MESSAGES_MAP` maps `Net::OpenTimeout`, `ReadTimeout`, `ECONNREFUSED`, `SocketError`, `OpenSSL::SSL::SSLError` and similar to friendly messages, then raises `APIConnectionError` with "Request was retried N times" (`handle_network_error`).

## 8. Retries

[`api_requestor.rb#L122`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_requestor.rb#L122) `should_retry?`:

```ruby
return false if num_retries >= config.max_network_retries
case error
when Net::OpenTimeout, Net::ReadTimeout, Net::HTTPFatalError then true
when EOFError, Errno::ECONNREFUSED, Errno::ECONNRESET, Errno::EHOSTUNREACH,
     Errno::ETIMEDOUT, SocketError then true
when Stripe::StripeError
  return false if error.http_headers["stripe-should-retry"] == "false"
  return true  if error.http_headers["stripe-should-retry"] == "true"
  return true  if error.http_status == 409
  return true  if error.http_status == 429 && error.code == "lock_timeout"
  true if error.http_status >= 500
end
```

`sleep_time` (L167): `min(0.5 * 2**(n-1), 5)`, then multiplied by `0.5*(1+rand)` (jitter between 50% and 100%), then floored at `initial_network_retry_delay`. **`Retry-After` is never read** (grep finds no match in `lib/`). Plain 429 rate limits are **not** retried.

- **Automatic idempotency** (L1048–1053): `headers["Idempotency-Key"] ||= SecureRandom.uuid` for `:post`/`:delete` when `api_mode == :v2 || max_network_retries > 0`. The same key is reused across retries because headers are built once, before the `retry` loop.
- **Net::HTTP retries are disabled**: `connection.max_retries = 0` ("stripe-ruby owns retries"), see [`connection_manager.rb#L187`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/connection_manager.rb#L187).
- **Docs**: the `Stripe-Should-Retry` values are `true`/`false`/absent, and "Stripe SDKs respect this header automatically". Keys are kept "for at least 24 hours" ([docs.stripe.com/error-low-level](https://docs.stripe.com/error-low-level)). Replays carry `Idempotent-Replayed: true`.

## 9. HTTP layer, instrumentation, logging, telemetry, User-Agent

- **`ConnectionManager`** ([`connection_manager.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/connection_manager.rb)):
  - Requests go through `Net::HTTPGenericRequest`, executed under a mutex.
  - `keep_alive_timeout = 30` ("reused Go's default").
  - On any `Exception`, `discard_connection` finishes the socket so that a `Thread#raise` (e.g. a Rack::Timeout) can't leave a half-read response for the next request (L154). Worth copying.
  - Streaming: `connection.request(req, body, &block)` with `response.read_body(&chunk)`, only for status < 400.
- **Request pipeline** (`execute_request_internal`, then `execute_request_with_rescues`, L635): validate path, merge options, encode query/body, build headers, then the retry loop. That loop runs log, `notify_request_begin`, send, parse, `handle_error_response`, log and `notify_request_end`.
- **Instrumentation** ([`instrumentation.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/instrumentation.rb)) is a global pub/sub with `subscribe(topic, name = rand, &blk)` / `unsubscribe` / `notify`:
  - Topics: `:request_begin` and `:request_end` (`:request` is a legacy alias).
  - `RequestEndEvent` is frozen and carries `duration, http_status, method, num_retries, path, request_id, request_header, request_body, response_header, response_body, user_data`.
  - `user_data` is a hash that flows from begin to end.
  - Note: the subscriber registry is a plain class-level Hash with no mutex.

  ```ruby
  Stripe::Instrumentation.subscribe(:request_end) do |e|
    StatsD.distribution("stripe_request", e.duration, tags: { code: e.http_status, retries: e.num_retries })
  end
  ```
- **Logging**:
  - `Util.log_info/debug/error` emit logfmt (`message=... key=value`).
  - They go to `logger` if set, else to stdout/stderr gated by `log_level`, with colorized keys on a TTY ([`util.rb#L187`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/util.rb#L187), `log_internal` L467).
  - Info-level logs omit bodies; debug logs bodies and a Dashboard link for the request ID.
  - Quirk: `log_internal` is always passed `Stripe.logger` (global) even when a per-config logger exists (L193/203/213).
- **Headers** (`request_headers`, [`api_requestor.rb#L1024`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_requestor.rb#L1024)):
  - `User-Agent: Stripe/v1 RubyBindings/21.0.0 [AppName/1.2 (url)] [AIAgent/claude_code]`
  - `Authorization: Bearer <key>`
  - `X-Stripe-Client-User-Agent` as JSON `{bindings_version, lang, lang_version, engine, platform, telemetry_id, application}`
  - `X-Stripe-Client-Telemetry` carries the **previous** request's `{request_id, request_duration_ms, usage}` from a `Queue` (best effort).
  - `Stripe-Version`, `Stripe-Account`, `Stripe-Context`, `Idempotency-Key`, plus any user headers.
  - `TelemetryId` persists a random ID at `~/.config/stripe/telemetry_id` ([`telemetry_id.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/telemetry_id.rb)). For a HIPAA SDK we should not write files to the user's home directory.
- **`set_app_info`**: `Stripe.set_app_info("MyPlugin", version: "1.2.34", url: "https://…", partner_id: nil)` ([`lib/stripe.rb#L180`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe.rb#L180)). It is appended to the UA by `format_app_info`.
- **`Stripe-Notice`** response header: the SDK prints a `warn` (suppressible with `STRIPE_SUPPRESS_NOTICES=true`; `maybe_emit_stripe_notice`).

## 10. Webhooks

[`lib/stripe/webhook.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/webhook.rb):

```ruby
event = Stripe::Webhook.construct_event(payload, sig_header, secret, tolerance: 300)
Stripe::Webhook::Signature.verify_header(payload, sig_header, secret, tolerance: 300)  # => true or raises
Stripe::Webhook::Signature.compute_signature(Time.now, payload, secret)   # test helper
Stripe::Webhook::Signature.generate_header(Time.now, sig)                # "t=..,v1=.."
```

- **Scheme**: `EXPECTED_SCHEME = "v1"`. The signature is `HMAC-SHA256(secret, "#{t.to_i}.#{payload}")` as hex. The header is split on `,\s*`, then each item on the first `=`. **Any** matching `v1` passes, which covers secret rotation ("Stripe generates one signature per secret until expiration", [docs](https://docs.stripe.com/webhooks/signature)).
- **Constant-time** comparison uses `Util.secure_compare` (length check, then XOR fold; [`util.rb#L371`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/util.rb#L371)). Blank or whitespace-only secrets are rejected.
- **Tolerance**: `DEFAULT_TOLERANCE = 300`. Only old timestamps are rejected (`timestamp < Time.now - tolerance`); future timestamps are not checked. `tolerance: nil` on `verify_header` disables the check.
- **Error messages**: v21 adds diagnostic error messages driven by unsigned debug metadata in the header (`secret=whsec_***PzVt,destination=we_x,payload=<sha256 suffix>`). These say "wrong secret" or "body was altered" without trusting that metadata for authentication.
- **Docs**: the body must be raw, the integration "must accept unknown entries and must not depend on a fixed entry count or order", and `v0` appears only on test events.
- **Thin events (v2)**:
  - `client.parse_event_notification(payload, sig, secret)` verifies the signature, then builds a typed `Stripe::Events::<Type>EventNotification`, or `UnknownEventNotification` for types newer than the SDK ([`stripe_client.rb#L67`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_client.rb#L67)).
  - The notification carries `id, type, created, context, related_object`. It fetches lazily with `fetch_event` / `fetch_related_object` through a client already scoped to `context` ([`resources/v2/core/event_notification.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/resources/v2/core/event_notification.rb)). Note that it `CGI.escape`s the ID from the body.
  - `client.notification_handler(secret) { |notif, client, details| fallback }` returns a router with generated `on_<event_type>` registration methods, a `pre_handle` hook (dedup/logging; returning false stops) and "no new callbacks after the first event" ([`stripe_event_notification_handler.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_event_notification_handler.rb)).
  - Cloud envelopes (EventBridge `detail`, CloudEvents `data`) are unwrapped by the `*_without_verification` methods.

## 11. Raw requests, uploads, binary downloads

- **Raw**: `client.raw_request(:post, "/v1/beta_endpoint", params: {...}, opts: {stripe_version: "..."}, base_address: :api)` returns a `StripeResponse` (`data`, `http_body`, `http_status`, `http_headers`, `request_id`). Follow with `client.deserialize(resp.http_body)` to get objects ([`stripe_client.rb#L107`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/stripe_client.rb#L107)).
- **Multipart upload**: `FileService#create` checks that `params[:file]` responds to `#read` and sets `opts[:content_type] = multipart/form-data`. It posts to the `:files` base ([`services/file_service.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/services/file_service.rb)). [`multipart_encoder.rb`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/multipart_encoder.rb) is hand-written: boundary `SecureRandom.hex(30)`, the filename comes from `File#path` or defaults to `"blob"`, and the **whole file is read into a String in memory** (no streaming upload).
- **Binary download**: generated `pdf(id, params, opts, &read_body_chunk_block)` uses `request_stream` against `base_address: :files` ([`services/quote_service.rb#L60`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/services/quote_service.rb#L60)). A block is **required** (`execute_request_stream` raises without one, [`api_requestor.rb#L292`](https://github.com/stripe/stripe-ruby/blob/94490f760b89/lib/stripe/api_requestor.rb#L292)). The method returns a `StripeHeadersOnlyResponse`. Chunks are only streamed for status < 400; errors are still parsed as JSON.

  ```ruby
  File.open("q.pdf", "wb") { |f| client.v1.quotes.pdf("qt_123") { |chunk| f.write(chunk) } }
  ```

- **README structure**: Installation/Requirements, Usage (StripeClient), Per-request config, StripeClient vs legacy, property access, `last_response`, proxy, API version, CA bundle, retries, timeouts, logging, notices, instrumentation, plugin `set_app_info`, telemetry opt-out, types (RBI policy), preview SDKs, custom requests, support, development.

## Adopt / Adapt / Skip for teachmehipaa-ruby

| Stripe pattern (citation) | Verdict | teachmehipaa-ruby decision |
|---|---|---|
| Zero-dep stdlib `net/http` + `json` + `openssl` (§1) | **Adopt** | Same. Declare `logger` (and `base64` if needed) explicitly, since these became bundled gems in Ruby 3.4+. Floor at Ruby 3.2 to match our LTS window and support `Data.define`. |
| Sorbet RBI only (§1) | **Adapt** | Ship **RBS** in `sig/` (generated from OpenAPI) as the primary types, idiomatic with Steep and ruby-lsp. Optionally generate RBI with the same generator. Keep the "types change in minors" policy. |
| `autoload` + `eager_load!` + Railtie (§1) | **Adapt** | Our surface is small, so use Zeitwerk (`Zeitwerk::Loader.for_gem`) or plain requires. Either way, provide `TeachMeHIPAA.eager_load!` for pre-fork servers. |
| Global `Stripe.api_key` + `Stripe::Customer.create` legacy style (§2) | **Skip** | Client-only: `TeachMeHIPAA::Client.new(client_id:, client_secret:, environment: :sandbox)`. Global mutable credentials are a multi-tenant footgun, and Stripe itself is deprecating them. |
| StripeClient with `v1`/`v2` service trees (§2, §4) | **Adapt** | `client.organizations.enrollments.list(org_id)`. One API version means no `v1/v2` split, but nest services to mirror resource paths. Instantiate sub-services lazily (memoized). |
| Per-client config imports transport settings from global (§2 gotcha) | **Skip** | Every option (timeouts, retries, logger, proxy, CA, base URL) is per client and immutable after construction (`Data`/frozen config). Use `client.with_options(timeout: 5)` to derive a copy. |
| Static secret API key (§2) | **Adapt** | `TokenProvider` interface:<br>• `ClientCredentials`: caches the 15-min JWT behind a `Mutex`, refreshes when within 60s of `exp` and on the first 401, single-flight so concurrent threads share one refresh.<br>• `AuthorizationCode`: PKCE helpers plus rotating refresh tokens, with an `on_refresh` callback so apps persist the new refresh token atomically.<br>• `StaticToken` for testing.<br>Never log tokens; override `#inspect`. |
| `StripeConfiguration` defaults: 30/80/30s timeouts, 2 retries (§3) | **Adopt** | open 10s, read 60s, write 30s, `max_retries: 2`. Validate in the constructor (no `to_i` coercion that truncates 0.5 to 0). |
| Live/test via key prefix, single `api_base` (§3) | **Adapt** | `environment: :live / :sandbox` maps to base URLs, with a `base_url:` override for local and stripe-mock-style testing. Assert that the token audience or issuer matches the environment to avoid cross-env calls. |
| Thread-local `ConnectionManager`, persistent Net::HTTP, 30s keep-alive, `max_retries = 0`, discard on `Exception` (§3, §9) | **Adopt** | Copy the semantics, but scope per client instance (one manager per thread per client, via `Thread.current` keyed by client ID or a small `Queue`-based pool). | Generated services: explicit methods with `CGI.escape` path IDs (§4) | **Adopt** | Generate from our OpenAPI 3.1. Always escape path params. Use keyword args for path IDs (`retrieve(org_id:, id:)`) or positional following Stripe's order; pick one and generate consistently. |
| `APIOperations` mixins and the `custom_method` metaprogramming (§4) | **Skip** | Stripe itself no longer uses `custom_method` in generated code. Generate explicit methods. AIP-136 `:cancel` becomes `enrollments.cancel(org_id, id)`, which posts to `/organizations/{orgId}/enrollments/{id}:cancel`. The colon must **not** be escaped: escape the ID segment, then append the `:verb` literal. |
| `StripeObject` dynamic `method_missing` accessors (§4) | **Adapt** | Generate `Data.define` (or frozen value classes) per schema with typed readers. | Typed `RequestParams` with explicit-nil tracking (§4) | **Adapt** | Accept plain hashes plus optional generated param classes. Preserve explicit `nil` for JSON PATCH, which our API needs. |
| Second-hash per-request opts `(params, opts)` (§5) | **Adapt** | Use **keyword** `request_options:` (or `**opts` with reserved keys): `idempotency_key:`, `if_match:` (ETag), `timeout:`, `max_retries:`, `headers:`. A positional second hash is unidiomatic and easy to confuse with params in Ruby 3. |
| `ListObject#auto_paging_each` returning an Enumerator (§6) | **Adopt** | `list` returns `Page` (`data`, `next_cursor`, `#next_page`) and `#auto_paging_each` / `#each_item` returns an `Enumerator::Lazy`-friendly enumerator. | Search result `page` token (§6) | **Skip** | Not applicable unless we add search. The same `Page` abstraction covers it. |
| Error hierarchy keyed by status, carrying `http_status/http_body/json_body/headers/code/request_id` (§7) | **Adapt** | Root `TeachMeHIPAA::Error`.<br>• `APIError` subclasses by status: `BadRequestError`(400), `AuthenticationError`(401), `PermissionDeniedError`(403), `NotFoundError`(404), `ConflictError`(409), `PreconditionFailedError`(412, ETag), `UnprocessableEntityError`(422), `RateLimitError`(429), `InternalServerError`(5xx).<br>• `ConnectionError`, `TimeoutError`, `SignatureVerificationError`, `OAuthError` (RFC 6749 codes, as Stripe's `OAuth::*`).<br>• Parse **RFC 9457 problem+json**: `type, title, status, detail, instance` plus extensions such as `errors[]`, exposed as `#problem`.
